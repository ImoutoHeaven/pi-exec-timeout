# Pi shell timeout

为 Pi 1.1.0 / 1.2.0 的 `bash` 和 `powershell` 工具统一设置执行超时，默认 **240 秒（4 分钟）**。`powershell` 内置执行器仅支持 Windows。

## 加载与配置

在本目录中临时加载：

```sh
pi -e ./index.ts
```

在启动 Pi 前设置 `PI_SHELL_TIMEOUT_SECONDS`，单位为秒。PowerShell 7 示例（在本目录执行）：

```powershell
$env:PI_SHELL_TIMEOUT_SECONDS = "120"
pi -e ./index.ts
```

在本目录运行 `pi install .` 可将此本地包加入个人 Pi 配置；扩展也可以通过项目配置加载。当前项目仅提供插件文件，启用由使用者选择。

配置在扩展加载时读取。未设置时使用 `240`；显式设置时必须是大于 `0`、不超过 `2147483.647` 的有限数值，可以使用小数。空值或非法值会使两个 shell 工具的调用返回错误并阻止执行，其他工具保持原行为。

## 执行边界与历史不变性

扩展只注册一个公开的 `tool_call` 处理器，按精确工具名匹配 `bash`、`powershell`，给执行参数的 `timeout` 字段赋值：缺少时新增，已有时覆写，包括模型传入的更短或更长超时。

直接调用、codemode 中的 `tools.bash(...)` / `tools.powershell(...)`，以及经 `ctx.executeTool()` 发起的调用，都经过 Pi 的工具调用管线，因此使用相同规则。

Pi 在校验工具参数时先克隆原始参数。扩展只修改这个执行副本，保留工具声明、工具选择、system prompt、原始聊天消息、历史条目及已保存历史前缀。正常的新消息和工具结果由 Pi 继续追加；扩展自身不注入上下文或声明变更。

范围只包含这两个工具。用户 `!` 命令、扩展直接使用的 `pi.exec()`、FastExec、IDA 和 codemode 整段脚本的超时均沿用各自行为。

超时后的终止、取消、输出处理和错误结果由 Pi 原生执行器负责。这是进程执行超时，不是覆盖所有文件系统操作的绝对工具返回期限。工具调用处理器按扩展顺序运行；后续扩展若再次修改 `timeout`，会影响最终生效值。

## 验证

```sh
bash test/docker.sh
```

脚本使用只读源码挂载和临时容器，分别安装同版本的 Pi 1.1.0、1.2.0 依赖，运行测试及严格 TypeScript 检查；宿主依赖保持原状。需要 Docker daemon 和下载测试依赖的网络访问。

测试覆盖默认值、环境变量、非法配置阻止执行、两个工具的直接与真实 codemode 调用、实际执行器收到的超时、其他工具不变、工具声明与 system prompt 不变、原始调用参数与历史前缀不变。真实死循环终止测试覆盖 bash；PowerShell 的真实执行测试仅在 Windows 上运行，在 Linux 容器中明确跳过。
